# Continuous acquisition operations

Read [current acquisition policy](current-acquisition-policy.md) and
[dedicated email operations](dedicated-email-operations.md) for the active policy.
The owner has removed the daily contact ceiling. The server worker handles durable
email events, replies, suppressions, follow-ups and funnel work. The supervised
local browser executor pulls discovery, qualification and permitted channel work
from the same persistent queue. Hourly oversight is not its execution trigger.

Use scripts/growth-review.ps1 -Action operator-state for health, outreach-status
for actual first-contact receipts and separate uncertainty, and email-status for
provider readiness. Do not manually seed acquisition work to make an autonomy
test pass. The planner replenishes an empty queue using retained evidence.

Keep one submission in flight and protect uncertain merchants from retry. A
separate incident hold stops accumulating ambiguous effects; it is not a contact
quota. Suppression and linked merchant history apply across channels.

The browser supervisor uses existing Skubase acquisition executor scheduled task.
After code deployment, drain active work before restarting it. Retained local
executor traces diagnose failures; durable DB evidence determines actual outcomes.
Never replace a missing receipt with an assumption of delivery.

The hourly oversight checks genuine replies and faults without duplicating the
executor. Complete the existing executive review once after 9 a.m. Pacific each
day. Unchanged monitoring remains quiet. Model/API dollar allocation stays UNKNOWN
where not measured; no paid fallback or provider subscription is authorized.

Business info@skubase.io and support@skubase.io remain operational mail. Dedicated
cold-email transport stays disabled until its documented setup and safe-test
requirements pass. Continue appropriate forms, useful public answers and individual
conversations while email setup is blocked.
